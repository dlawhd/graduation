# 요청 제한 3초 기준본과 5초 소량 진단

작성일: 2026-10-19, 한국 시간 기준.

## 목적과 경계

3초는 시험 도구가 요청 하나를 기다리는 최대 시간이며, 반드시 따라야 하는 표준이나 실제 앱의 공통 제한이 아니다. 5초 진단은 느린 요청이 완료되는지 관찰하기 위한 별도 조건이다. 서버 처리 속도가 개선됐다는 뜻으로 해석하지 않는다.

- 이전 3초 결과·실패 기록을 보존한다.
- 조회 성능 목표 p95(요청 중 약 95%가 끝나는 시간) 500ms 이하·오류율 1% 미만은 변경하지 않는다.
- CPU·Heap(자바 객체 저장 공간)·DB 연결·가용 메모리·수집 장애·재시작·OOM(메모리 부족 종료) 중단 기준도 유지한다.
- 앱·서버 설정, 인증 정책, DB 구조, 비용 발생 외부 API 경로는 변경하지 않는다.
- 진단 실패나 수집 장애는 성공으로 바꾸지 않고, 다음 단계로 올리지 않는다.

## 사용자와 정한 증가 순서

1. 4개 전용 계정의 순차 준비를 확인한다.
2. 통과하면 10개 계정 준비를 확인한다.
3. 통과하면 10 VU(동시에 반복 요청하는 가상 사용자 10명) 조회를 확인한다.
4. 해당 단계의 응답·자원·종료 후 회복 조건을 충족한 경우 50 VU로 올린다.

계정을 순차 로그인하는 것과 같은 수의 동시 부하는 다른 검사다. 어느 단계든 실패하면 중단한다. 100 VU 이상은 이 순서에 포함하지 않는다.
