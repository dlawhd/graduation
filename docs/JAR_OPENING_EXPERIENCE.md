# 저금통 타격·균열·파괴 연출

2026-11-06 로컬 구현·검증 기록이다. 운영 배포 확인은 포함하지 않는다.

## 사용자 제보와 원인

첫 구현은 실제 균열 대신 짧은 Y자 선을 별도로 얹고, 고정된 다섯 영역을 벌렸다.
금과 조각의 경계가 서로 달랐고 이미지 단독 디자인에서는 흰 배경까지 사각형으로 분리됐다.
사용자가 원한 것은 망치가 닿은 실제 저금통 표면에 금이 생기고 그 금을 따라 그림이 깨지는 동작이었다.
별도 장식 선과 고정 원형 분리는 제거했다.

## 수정한 흐름

1. 서버가 현재 저금통을 공개했다고 확인하면 연출을 표시한다.
2. 첫 두드림은 망치를 들어 올린 뒤 **280ms의 접촉 시점**에서 실제 그림에 첫 금과 틈을 만든다. 소리도 같은 접촉 시점에 낸다.
3. 두 번째에는 첫 균열에서 이어진 더 넓은 균열이 생긴다. 금은 타격 후에도 표면에 남는다.
4. 세 번째에는 균열 전체가 열리고 **그 경계를 그대로 사용하는 12조각**이 회전하면서 아래로 떨어진다.
5. 조각이 사라지면서 편지가 보인다. `추억 보러가기`는 기존 쪽지 목록으로 이동한다.

`건너뛰기`, `소리 끄기`, `조금 있다 보기`, Esc를 지원한다.
요청에 따라 하단 **움직임 줄이기 버튼·열린 시간·구분선 영역을 제거**했다.
OS의 움직임 줄이기 설정은 자동 반영하며, 이 경우 타격 단계와 완료 상태를 정적으로 보여준다.

## 금과 조각을 함께 만드는 방법

- 원본 앞면을 480×480의 같은 좌표 공간으로 취급한다.
- 정해진 12개 분할점으로 평면을 나누고, 인접 조각의 공통 경계를 한 번만 생성한다.
  경계에는 작은 굴곡을 넣으며 양쪽 조각이 정확히 같은 좌표를 반대 방향으로 사용한다.
- 도면 또는 읽은 이미지 윤곽 안의 경계 교점을 타격 위치로 선택한다. 망치의 끝과 균열 시작점도 이 위치를 공유한다.
- 타격점에서 연결된 경계 순서로 균열을 확장한다. 금을 다른 곳에 임의로 그리지 않는다.
- 같은 경로를 원본의 투명한 틈·어두운 균열·밝은 모서리·조각 자르기에 사용한다.
- 마지막에는 중심 그림을 별도로 남기지 않는다. 원본 전체가 금을 따라 분리된다.

도면과 이미지 자체를 수정·저장하지 않는 **2D 표면 파괴 연출**이다. 원본 쪽지 사진은 기존 데이터로 그대로 보관된다.
SVG·Canvas·CSS 기능을 사용하며 새 라이브러리나 물리 엔진은 추가하지 않았다.

## 실제 디자인·흰 배경·권한

- 저장된 `JarCustomDesignVisual`을 사용해 실제 모양·사진 배치·장식·투입구를 그린다.
- 준비된 틀·동물·직접 만든 틀은 검증된 본체 도면으로 금을 표면에만 표시한다.
- 도면 없는 이미지 단독 디자인은 작은 480×480 Canvas에서 실제 윤곽을 읽는다.
  거의 흰 외곽이 대부분인 경우 **바깥과 연결된 흰색만** 연출용 마스크에서 제외한다.
  닫힌 눈·무늬 내부의 흰색과 유색 사진 배경은 임의로 제거하지 않는다. 사진 속 모든 사물을 자동으로 분리하는 기능은 아니다.
- 브라우저의 교차 출처 제한이 있는 이미지는 서버가 발급한 기존 `imageTextureUrl`을 사용한다.
  기존 `openTextureSource`가 허용하는 `/api/v1/jars/{id}/design/texture?part=IMAGE`에만 인증 API를 사용한다.
  임의 외부 URL에 로그인 정보를 보내지 않는다. 저장 URL·픽셀 내용은 로그에 남기지 않는다.
- 윤곽을 읽지 못하면 오류·기존 상세 재시도·건너뛰기를 제공한다. 다른 그림으로 교체해 깨진 것처럼 표시하지 않는다.
- 새 API·DB·권한 변경은 없다. 이미지 단독 윤곽 처리에 기존 텍스처 API를 한 번 사용할 수 있고, 매 타격마다 API를 호출하지 않는다.

## 안정성과 정리

- 클릭 입력과 실제 접촉을 별도 상태로 구분한다. 접촉 전에는 금·소리를 발생시키지 않는다.
- 두드리는 동안 연속 클릭을 막고, 이전 타격 타이머·건너뛰기 뒤 타이머가 완료 상태를 되돌리지 못하게 한다.
- 모든 조각 그림과 윤곽이 준비된 뒤 두드리기를 허용한다. 실패·8초 무응답이어도 추억으로 이동할 수 있다.
- 창 종료·저금통 변경·이미지 재시도 시 이전 요청·타이머·오디오·임시 Blob URL을 정리한다.
- native `dialog`로 배경 입력을 차단하고 Tab 초점을 안에 유지한다. 닫으면 기존 초점·스크롤을 복구한다.
- 서버 공개 상태만 사용한다. 연출이나 세 번 두드리기가 서버의 공개 시각·열람 권한을 바꾸지 않는다.
- 기존 사용자·저금통별 탭 확인 기록과 중복 자동 표시 방지를 유지한다.
  열린 상세 화면의 **추억 열기 다시 보기**로 재실행할 수 있다.

## 검증

- 프론트 Node 테스트 **314개 통과**. 이 연출 관련 18개에는 전체 면적 보존, 두 조각과 균열 좌표 일치,
  타격점 연결, 단계별 확장, 접촉 전 무손상, 흰 눈 보존, 오디오 준비·정리를 포함한다.
- 프론트 빌드 성공. 기존 500kB 초과 JS 청크 경고는 남아 있다.
- Chrome 390px·1280px에서 준비된 틀·레서판다·직접 만든 틀·이미지 단독·흰 배경 캐릭터·기존 인증 텍스처 경로를 확인한다.
  실제 금·조각 낙하, 중복 클릭, 소리·접촉 타이밍, footer 제거, OS 움직임 설정, 실패·재시도·건너뛰기·정리도 검사한다.
- 실제 `JarDetailPage`의 REST 공개 감지 → 쪽지 목록 → 확인 기록 → 중복 표시 방지 → 다시 보기를 별도 검사한다.
- 공개 뒤에도 **내가 넣은 쪽지**를 유지하고, 기존 전체 열람 버튼은 **전체 쪽지**로 구분한다.
  본인 목록은 기존 작성자 조건 API를 사용하며, 다른 멤버의 쪽지를 본인 목록에 섞지 않는다.
- 1280×700·390×640의 작은 창에서도 두드리기·나중에 보기 버튼이 화면 안에 들어오는 것을 확인했다.
- 연출을 닫은 뒤 기존 댓글 페이지 조회·실패 재시도·깊은 답글·300자 입력 제한 검사도 통과했다.
  첫 동시 실행에서는 댓글 버튼 클릭이 시간 초과됐고, 다른 검사가 끝난 뒤 단독 재실행에서 통과했다.

원본 검사 로그는 로컬 `build/jar-fracture-unit.log`, `jar-fracture-build.log`, `jar-fracture-browser.log`에 보관한다.
`build/jar-opening/impact-*`, `second-tap-*`, `shattering-*`, `opaque-cracked-*`, `opaque-second-*`, `opaque-shattering-*`는
생성 시안이 아닌 실제 컴포넌트를 합성 사진으로 실행한 캡처다.

실제 개인 사진·운영 배포·기기 스피커 청감 검사는 로컬 합성 데이터 검증에 포함하지 않는다.
