## 2. 기존 동작

문의 작성은 흰 카드와 일반 입력 테두리, 브라우저 기본 파일 선택 표시를 사용했다. 편지 스타일의 첫 적용에서는 작성 화면에만 짙은 헤더와 아이보리 배경이 있어 도움말에서 이동할 때 차이가 컸다. 이번 정리에서는 서비스 공통 헤더를 기존 흰색으로 유지하고 도움말·문의 본문의 디자인을 통일했다.

비로그인은 `로그인·계정` 고정 유형, 로그인 사용자는 아홉 유형 중 선택한다. 문의 본문을 먼저 접수하고 첨부만 실패하면 같은 문의에 다시 올리는 구조는 유지한다.

## 3. 변경한 동작

선택한 ‘편지 같은 문의’ 예시의 아이보리 배경, 짙은 초록색 접수 버튼, 세이지색 유형 배지와 안내 띠를 적용했다. 공통 헤더와 초록색 로고는 기존 모습으로 유지한다. 도움말·문의 작성·내 문의·운영 문의·답변 화면은 같은 본문 너비, 제목 시작 위치와 크기, 카드 테두리와 배경, 버튼 기준을 사용한다.

작성 폼 제목은 밑줄형 입력란, 내용은 크기를 늘릴 수 있는 작성 영역이다. PC의 작성 화면에만 저금통·봉투 선 그림을 표시하고 모바일·목록·답변 화면에서는 숨긴다. 생성 이미지 자체를 배경으로 붙이지 않고 실제 입력 가능한 화면으로 구현했다.

파일 선택은 간결한 첨부 버튼으로 바꾸고 미리보기·제거·공유 동의·재시도는 유지했다. 비로그인 답변의 브라우저 제한과 보관 기간도 표시한다. 접수 버튼 문구는 두 작성 화면 모두 ‘문의 접수하기’로 통일하고 저장 중·첨부 확인 중·재시도 문구는 구분한다.

일반 문의의 유형은 `사진 업로드 → AI 생성·결과 품질 → 3D 표시 → 쪽지·댓글·채팅 → 초대·권한 → 사용 방법 → 기능 제안 → 로그인·계정 → 기타` 순서다. 표시 순서만 바꾸며 API 식별자·기존 문의 데이터·기본 선택값은 변경하지 않는다.

## 4. 변경 이유와 범위

화면을 이동해도 같은 서비스 안에 있다는 느낌을 유지하기 위한 변경이다. 로그인·비로그인은 같은 레이아웃과 폼을 사용하되 유형과 권한은 기존대로 구분한다. 문의 상세의 대화·관리자 처리·목록은 표시만 맞추며 요청·권한 검사·페이지 이동 로직은 유지한다.

## 5. 성능·보안·유지보수

- 새 라이브러리, 외부 글꼴, 이미지 요청, 추가 API 호출 없이 CSS와 작은 SVG로 구성했다.
- 공통 헤더를 별도로 덮어쓰지 않고, 전용 클래스가 있는 문의 본문에만 스타일을 적용한다.
- 기존 요청 중복 방지, 화면 이동·계정 전환 후 늦은 응답 무시, 첨부 동의와 실패 재시도 로직을 유지했다.
- 파일 입력은 키보드로도 선택창을 열 수 있다. 입력 글자 크기는 모바일에서 16px로 유지했다.
- 이번 작업은 프론트 표시 변경이며 백엔드 API·DTO·DB·IAM 권한은 변경하지 않았다.
