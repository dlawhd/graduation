# 귀여운 2D와 손그림 프롬프트 비교 준비

## 현재 상태 — 서버 비교 완료, 개선 프롬프트 적용 보류

2026-10-06 운영 재시험에서 귀여운 2D 후보 #131과 손그림 후보 #134는
Cloudflare HTTP 400, 코드 3030, `AI_ERROR_UNRECOGNIZED`로 실패했다.
이 신호는 오류 설명이 있지만 현재 허용 목록으로 원인을 구분하지 못했다는 뜻이다.
프롬프트 길이, 콘텐츠 정책 또는 제공자 내부 문제 중 하나로 확정하지 않는다.

위 내용은 당시 #131/#134 로그로 확인할 수 있었던 범위다. 이후 새 비교 요청 4개는
모두 제공자의 출력 차단 문장으로 실패한 것이 확인됐다. 과거 후보의 원문을 복구하거나
모든 코드 3030을 같은 이유로 소급 분류한 것은 아니다. 아래 새 비교 결과를 따른다.

기괴는 이번 비교와 변경 대상에서 제외한다. 픽셀, 부드러운 3D, 수채화도 변경하지 않는다.
기존 프롬프트 파일, `AiPromptCatalog` 매핑, API, DB, 이미지 입력 및 콘텐츠 심사는 그대로다.

## 준비한 후보

후보는 `src/test/resources/ai/prompt-candidates/`에만 있다.
운영 `bootJar`에 포함되지 않고 사용자 생성 요청에도 사용되지 않는다.

| 스타일 | 기존 운영 조합 | 비교 후보 | 문자 수 (LF 기준) |
| --- | --- | --- | --- |
| 귀여운 2D | BASE_V2+CUTE_2D_V2 | cute-2d-v3.txt, 독립 프롬프트 | 3,528 → 1,167 |
| 손그림 | BASE_V2+HAND_DRAWN_V1 | hand-drawn-v2.txt, 독립 프롬프트 | 4,182 → 1,247 |

반복되는 보존 지시를 모으고 원하는 표현 방식을 먼저 설명한다.
대상 수, 정체성, 상대 배치, 실루엣, 표정, 작은 식별 표시, 색상 위치,
흰 영역, 추상 선과 빈 공간, 흰 배경 및 전체 구도 보존 규칙은 유지한다.
문자 수 감소는 성공률, 지연 시간 또는 비용 개선의 측정 결과가 아니다.

## 1. 구체적인 제공자 오류 확인

기존 애플리케이션은 제공자 오류 원문을 로그나 DB에 저장하지 않는다.
현재 로그에서 원문을 복원할 수는 없다. Cloudflare 관리 화면에 해당 이력이
보관돼 있는지 확인하고, 없으면 아래 시각과 CF-Ray로 제공자 측 확인이 필요하다.

| 대상 | 실패 시각 (UTC) | CF-Ray |
| --- | --- | --- |
| 귀여운 2D #131 | 2026-10-06 11:02:46 | a4642ca8acda88f8-ICN |
| 손그림 #134 | 2026-10-06 11:05:44 | a46431203c4a88f8-ICN |

원문에 입력 내용이 포함될 수 있으므로 토큰, 이미지, 전체 프롬프트나 응답을
공개 문서나 채팅에 붙이지 않는다. 원인이 확인된 경우에만 검증된 문장 형식을
고정 분류로 추가하며 단순 키워드 포함 여부만으로 콘텐츠 차단을 판정하지 않는다.
이 단계에서는 제공자에게 지원 요청을 보내거나 과거 후보의 구체적인 원인을 확인하지 못했다.

2026-10-06 로그인한 관리 화면에서는 Workers AI의 해당 모델 사용량을 확인했다.
AI Gateway는 초기 연결 안내였으며 기존 요청 로그 목록은 보이지 않았다.
따라서 과거 오류 원문을 확보한 것으로 기록하지 않는다.

## 2. 기존/개선 비교 — 실행 방법과 비교 조건

실제 호출용 인증과 비교 입력을 준비한 뒤 귀여운 2D 및 손그림 각각
기존 1회 + 후보 1회, 총 4회로 시작한다. 자동 재시도는 하지 않는다.

서버의 기존 인증을 사용하는 테스트 전용 `AiPromptComparisonTool`과
`tools/ai-prompt-compare/run.sh`를 준비했다. 전달용 ZIP은 Gradle의
`aiPromptComparisonBundle` 작업으로 만든다. 일반 `bootJar`에는 포함되지 않는다.
서버 준비/실행 명령과 비공개 오류 파일 주의사항은
[서버 실행 안내](../../tools/ai-prompt-compare/README.md)를 따른다.

`prepare`는 DB 읽기 전용 조회와 S3 GET으로 저장 장면을 준비하며 AI를 호출하지 않는다.
`run`은 동일 입력으로 최대 4회 호출하고 HTTP/이미지 검증 결과만 기록한다.
DB/S3 쓰기, 후보 선택, 원본 교체, 서비스 재시작과 콘텐츠 심사 변경은 없다.
실제 생성은 사용량이 발생하고, 명확한 정책/입력/인증/한도 오류면 남은 호출을 중단한다.
도구가 사용하는 별도 JVM은 운영 컨테이너의 자원을 공유하므로 실행 전 여유 자원을 확인한다.

오류 원문을 일반 로그에 추가하지 않는다. 비교 과정의 HTTP 오류만 관리자용
0700 폴더의 0600 파일에 제한적으로 보관한다. 이 파일은 원인 확인용 비공개 자료이며
채팅이나 Git에 첨부하면 안 된다. 공유용 `*.safe.*` 요약과 분리한다.
과거 #131/#134의 원문을 복구하는 도구가 아니며 새로운 비교 실패의 응답만 보관한다.

- 두 조건에 동일한 **AI 입력 PNG 바이트**를 사용한다. 저금통 SVG를 합성하거나
  원본을 새로 자르지 않는다. Draft의 저장 원본과 저장한 `aiInputPhotoFrame`을
  `JarAiInputImageProcessor.prepare`로 처리한 장면이 비교 기준이다.
- 같은 모델, 입력 이미지 1개, 1024×1024 출력, 같은 명시적 seed를 사용한다.
- 기존 운영 시도는 `seedProvided=false`였으므로 #131/#134와 새 후보만으로
  통제된 A/B 비교를 했다고 주장하지 않는다. 동일 seed도 완전한 재현을 보장하지 않는다.
- HTTP 결과와 안전한 오류 분류, 호출 시간, 이미지 검증 결과를 기록한다.
- 성공한 경우 원본 대상 누락/추가, 배치와 표정, 색상, 전체 구도,
  귀여운 평면 표현 또는 색연필 질감이 유지되는지 사람이 확대 비교한다.
- 한 쌍의 비교는 품질 점검이며 성공률 개선의 통계적 근거가 아니다.
- 비교 이미지는 로컬의 Git 제외 경로에만 두고 기존 후보와 원본은 삭제하지 않는다.
  제공자 성공만으로 Rekognition 등 운영의 후속 심사까지 통과했다고 표현하지 않는다.

## 3. 서버 비교 결과 — 사용자 제공 출력과 비공개 응답 검사

2026-10-06 사용자가 운영 서버에서 사전 점검과 4회 비교 명령을 실행했다.
사전 점검은 `PREFLIGHT_OK draftId=44 input=480x480 plannedCalls=4 aiCalls=0`였다.
같은 입력과 seed 20261006을 사용한 새 비교 결과는 다음과 같다.

| 비교 요청 | HTTP / 코드 | 확인한 원인 신호 | 제공자 요청 시간 | CF-Ray |
| --- | --- | --- | --- | --- |
| CUTE_2D_OLD | 400 / 3030 | OUTPUT_FLAGGED | 13,074ms | a464856bda683d84-ICN |
| CUTE_2D_NEW | 400 / 3030 | OUTPUT_FLAGGED | 11,214ms | a46485baea0e309d-ICN |
| HAND_DRAWN_OLD | 400 / 3030 | OUTPUT_FLAGGED | 8,875ms | a4648600d85732a2-ICN |
| HAND_DRAWN_NEW | 400 / 3030 | OUTPUT_FLAGGED | 14,605ms | a46486386a42c02f-ICN |

사용자가 확인한 귀여운 2D 기존 요청의 응답과, 원문을 출력하지 않는 전체 문장
일치 검사에서 네 요청 모두 제공자의 **생성 결과 차단**으로 확인됐다.
정확한 내부 판정 항목, 원본의 부적절함 또는 오탐 여부는 확인하지 못했다.
오류 본문의 UUID나 전체 JSON 원문은 이 문서와 테스트에 복사하지 않는다.

`COMPARE_DONE moderation=NOT_RUN dbWrites=0 s3Writes=0 productionApply=NO`로 종료됐다.
생성 이미지가 없어 품질 비교는 수행할 수 없었다. 프롬프트 축약만으로 해결되지 않았으며
개선 후보는 운영에 적용하지 않는다. 1회씩 실패한 결과를 전체 성공률이나 성능 개선으로
일반화하지 않는다. 추가 AI 호출이나 필터 우회는 수행하지 않는다.

로컬 분류 보강은 해당 전체 문장과 선택적 UUID 형식만 허용한다. 반복 `AiError:` 접두사를
제거한 뒤 일치한 경우에만 `OUTPUT_IMAGE_FLAGGED` 고정 신호를 기록한다.
HTTP 400/200 및 코드 3030이면 기존 `PROVIDER_CONTENT_POLICY_REJECTED` 화면 안내로
연결하며, 원본이 부적절하다고 단정하지 않고 즉시 재시도를 권하지 않는다.
상충하는 입력 오류, 다른 코드/HTTP 상태, 사용자 인용이나 변형 문장은 기존 일반 분류를 유지한다.
이 수정은 실패 이유 안내의 개선이며 생성 성공 문제를 해결하거나 배포한 기록은 아니다.

## 4. 품질 확인 후 적용 — 보류

원본 보존과 스타일 품질이 확인된 후보만 새로운 운영 리소스로 승격한다.
현재 운영 파일을 덮어쓰지 않고 새 버전과 Catalog 매핑을 함께 반영한다.
귀여운 2D와 손그림 외의 매핑과 공통 BASE_V2는 바꾸지 않는다.
그 후 회귀 테스트, 배포 및 실제 Draft 흐름을 별도로 검증한다.

## 로컬 회귀 검증

`AiPromptCandidateTest`는 후보의 보존 규칙, 길이, 테스트 전용 위치 및
운영의 기존 6개 조합이 유지되는지 검사한다. 외부 AI를 호출하지 않는다.
Cloudflare 관련 회귀 테스트도 모의 응답을 사용한다.
실제 AI 성공 여부와 시각 품질은 이 테스트로 검증할 수 없다.

서버 도구 회귀 테스트는 실제 MariaDB 10.11의 임시 조회 스키마에서 배치 fallback,
종료/만료/정리/생성 중 Draft 거절, 스냅샷 변경 감지와 읽기 전용 트랜잭션을 검증한다.
이는 운영 DB/Flyway 적용 검증이 아니다. 외부 AI/S3는 테스트에서 호출하지 않는다.

2026-10-06 로컬 검증: 후보/Catalog/오류 분류/Client/비교 도구/MariaDB 조회의
관련 테스트 86개가 실패와 건너뜀 없이 통과했고 `bootJar` 및 전달 ZIP 빌드가 성공했다.
네트워크를 차단한 Java 17 Linux 컨테이너에서 기존 Boot Loader로 도구 로딩,
0600 저장/덮어쓰기 거절/심볼릭 링크 거절과 인증 누락 시 외부 호출 전 중단을 확인했다.
Bash 문법 검사도 통과했다. 이는 비교 도구 준비 당시의 로컬 검증 기록이다.
이후 서버 사전 점검과 실제 Cloudflare 비교는 위 사용자 제공 결과로 확인했으며,
품질 확인과 개선 프롬프트 운영 적용은 수행하지 못했다.

출력 차단 분류 보강 후에는 오류 분류/진단/Client/후보/Catalog/비교 도구/Generation Service/
오류 DTO 계약 테스트 139개와 프론트 오류 안내 Node 테스트 7개가 실패와 건너뜀 없이 통과했다.
`bootJar` 빌드와 `git diff --check`도 통과했다. 테스트는 모의 응답을 사용하며
이 보강 단계에서 실제 AI를 추가 호출하거나 DB 통합 테스트, 배포, 운영 화면 검증을 수행하지 않았다.

커밋 전 추가 검증에서는 `./gradlew test bootJar --offline`로 전체 백엔드 테스트를 실행했다.
MariaDB 통합 테스트를 포함한 124개 테스트 클래스, 총 1,743개 테스트가 실패/오류/건너뜀 없이
통과했고 서버 빌드도 성공했다. 프론트 오류 안내 테스트 7개와 스테이징 diff 검사도 통과했다.
실제 사진의 6개 스타일 생성 여부와 배포 후 화면 안내는 로그인 이후 별도 확인 대상이다.
