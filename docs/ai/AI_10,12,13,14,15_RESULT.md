## 10. 외부 원본 이미지 업로드·정규화 ✅

사용자가 Canvas 그림뿐 아니라 외부 이미지를 올릴 수 있도록 서버 처리 규칙을 구현했다.

### 허용 형식

- PNG
- JPEG
- WebP

GIF, 애니메이션 WebP, SVG, HEIC 등은 허용하지 않는다.

### 처리 규칙

1. 서버가 파일 확장자나 Content-Type만 믿지 않고 실제 바이트를 읽는다.
2. 최대 업로드 크기는 10MB다.
3. 원본은 최대 4096×4096, 총 16MP까지만 허용한다.
4. JPEG의 EXIF 회전 정보를 적용한다.
5. 세로·가로 이미지는 자르지 않고 비율을 유지한다.
6. 흰색 480×480 캔버스 중앙에 배치한다.
7. 투명 PNG/WebP 영역은 흰색으로 합성한다.
8. 최종적으로 항상 480×480 PNG로 만든다.
9. 정규화된 PNG를 Rekognition 심사하고, 같은 바이트를 Private S3에 저장한다.

즉, 심사한 이미지·Cloudflare에 전달할 이미지·S3 원본이 서로 달라지는 문제를 막았다.

## 12. AI 결과 이미지 검증·PNG 정규화 ✅

Cloudflare가 돌려준 결과를 그대로 믿지 않고 서버가 검증한다.

### 일반 AI 후보 규칙

- 응답 형식: PNG, JPEG, WebP 단일 프레임만 허용
- 최대 크기: 10MB
- 실제 디코딩 성공 필요
- 해상도: 정확히 1024×1024
- 저장 전 서버에서 PNG로 다시 인코딩

즉 Cloudflare가 1024×1024가 아닌 결과, 손상 이미지, 애니메이션 이미지, 너무 큰 이미지를 주면 후보 생성은 실패 처리한다.

## 13. Cloudflare Client 보완·계약 테스트 ✅

Spring Boot가 Cloudflare Workers AI REST API를 직접 호출하는 구조를 고정했다.

### 서버가 보내는 값

- Prompt
- `width=1024`
- `height=1024`
- 선택적 seed
- 원본 이미지
- PIXEL일 때 PIXEL Reference 이미지

### 안전장치

- Account ID, API Token, Model, Timeout은 환경변수로만 받는다.
- Token 등 비밀값을 코드에 넣지 않는다.
- HTTP timeout을 적용한다.
- 응답 본문과 Base64 이미지 크기를 제한한다.
- 429는 rate limit 오류로 구분한다.
- timeout, 일반 요청 실패, 잘못된 응답을 각각 구분한다.

실제 Cloudflare 호출은 아직 하지 않았고, HTTP 요청 형식과 응답·오류 처리는 단위 테스트로 검증했다.

## 14. PIXEL Java 후처리 ✅

PIXEL 스타일만 AI 결과를 한 번 더 픽셀 이미지로 가공한다.

### PIXEL_PP_V1 규칙

```
Cloudflare 1024×1024 결과
→ 흰 배경 합성
→ 64×64 bilinear 축소
→ 최대 24색 median-cut 팔레트
→ nearest-neighbor 확대
→ 480×480 PNG
```

### 의미

- 일반 AI 후보는 1024×1024 PNG로 보관한다.
- PIXEL 후보만 최종 480×480 PNG로 보관한다.
- 확대할 때 흐림 효과가 생기지 않도록 nearest-neighbor를 사용한다.
- 투명 색을 별도 팔레트로 남기지 않고 흰색 배경에 합성한다.

Python/Pillow PoC와 완전히 같은 픽셀 결과를 보장하는 단계는 아니다. 실제 Cloudflare 결과가 생기면 PoC 결과와 시각 비교를 별도로 진행한다.

## 15. AI Generation Service ✅

AI 후보 생성의 전체 서버 흐름을 구현했다.

### 전체 흐름

```
사용자 요청
→ Draft 잠금
→ PROCESSING Generation 생성 및 DB 커밋
→ DB 트랜잭션 종료

→ Private S3에서 원본 PNG 읽기
→ Cloudflare 호출
→ 결과 검증 및 PNG 정규화
→ PIXEL이면 Java 후처리
→ 최종 PNG Rekognition 심사
→ 후보 이미지를 Private S3에 저장

→ Draft 재잠금
→ 아직 PROCESSING이고 Draft가 ACTIVE일 때만 SUCCEEDED 처리
```

### 왜 DB 작업을 나눴나

Cloudflare와 S3는 네트워크 작업이라 오래 걸릴 수 있다.

그래서 다음처럼 처리한다.

```
짧은 DB 작업
→ 외부 작업
→ 짧은 DB 작업
```

이 방식으로 Cloudflare 응답을 기다리는 동안 DB 연결을 계속 점유하지 않는다.

### 동시성·실패 처리

- 같은 Draft에는 PROCESSING Generation을 하나만 허용한다.
- Cloudflare timeout, rate limit, 잘못된 응답은 FAILED로 기록한다.
- 원본 S3 읽기 실패도 FAILED로 기록한다.
- 후보 S3 업로드 실패도 FAILED로 기록한다.
- PIXEL 후처리 실패도 FAILED로 기록한다.
- AI 결과가 늦게 도착해도, 이미 timeout/실패/종료된 Generation을 성공으로 되살릴 수 없다.
- 후보 파일 업로드 후 성공 기록이 거절되면 방금 업로드한 S3 파일을 즉시 보상 삭제한다.

### 현재 아직 없는 것

- 사용자용 AI 생성 API/Controller
- React의 AI 생성 버튼·후보 보관함
- 10분 이상 PROCESSING 상태를 자동 실패 처리하는 Scheduler
- 실패·고아 S3 객체를 주기적으로 정리하는 Cleanup
- 실제 Cloudflare/AWS 운영 연동 테스트
