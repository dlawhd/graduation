# 그린 테두리 보존과 자연스러운 사진 창 — V52

V51 문서의 단색/좌표 전용 설명은 당시 구현이다. V52부터 새 그림판 틀은 다음 세 가지를 함께 보관한다. 이전 단색 틀과 기존 API 요청은 그대로 읽는다.

## 변경 동작과 주요 파일

- `JarDesignCanvas.jsx`: 획 완료/실행 취소 때 외곽선과 내부 사진 경계를 계산하고 투명한 480×480 테두리 PNG를 만든다. 색 선택은 다음 획에만 적용한다. PNG는 같은 탭의 sessionStorage에도 보관하며 용량 오류는 기존처럼 편집을 막지 않는다. 사진 원본은 기존처럼 메모리에만 보관한다.
- `bodyContours.mjs`, `customJarBody.mjs`: 안쪽 거리 마스크로 사진 공간을 계산한다. 깊은 오목한 부분을 사각형으로 대체하지 않는다. 좁은 연결부는 사진 창 없이 테두리로 남고 공간이 분리되면 여러 경계를 사용한다.
- `CustomJarBodyArtwork.jsx`, `body3DGeometry.mjs`, `body3DMesh.mjs`: 새 사진 경계를 2D 클리핑과 3D 실제 구멍에 함께 사용한다. 전체 보기의 안전한 사각형은 **사진 배치**에만 쓰며 구멍 모양을 바꾸지 않는다. 기존 단색 틀의 3D 축소 비율은 유지한다.
- `bodyArtworkPixels.mjs`, `CustomJarBody3D.jsx`: 그린 픽셀의 색을 보존하고 투명한 어깨/옆면만 가까운 테두리 색으로 이어준다. 뒷면은 같은 텍스처를 실제 회전으로 반전한다. CORS/텍스처 읽기 실패는 안내와 함께 2D로 복구한다.
- `JarBodyWorkshop.jsx`: 픽셀 그림과 좌표가 어긋나는 점 편집 전환에는 단색 변환 안내/동의를 제공한다. 한 단계 되돌리기로 원래 색과 질감을 복원할 수 있다.

## 입력·저장 계약

`customBody` JSON은 `points`, `color`, 선택 사항인 `photoContours`만 받는다. 로컬 `artworkUrl`은 JSON에 넣지 않는다.

- 외곽선: 기존 3~96점, 0.05~0.95 좌표와 색상 검증 유지.
- 사진 창: 최대 8개, 각 3~96점, 합계 384점. 외곽 밖/교차/중첩/너무 작은 경계는 서버와 프론트에서 거절한다.
- multipart `bodyArtwork`: 선택 사항, CUSTOM 전용. 실제 PNG 서명/480×480/1MB/단일 프레임/빈 그림 검사 후 재인코딩해 메타데이터를 제거한다. 투명도와 색은 유지한다.
- `JarBodyArtworkImageValidator`, `JarDesignDraftUploadService`: 테두리도 기존 이미지 심사를 별도로 통과해야 한다. AI에는 테두리를 합성하지 않은 사진 원본만 전달한다.
- V52: Draft/Design에 nullable `body_artwork_s3_key` 추가. `custom_body_json` 길이 제한 49,152자. 기존 V51 마이그레이션은 수정하지 않는다.
- 응답의 `bodyArtworkUrl`은 기존 소유권/멤버 권한 확인 뒤 발급하는 읽기용 Presigned URL이다. 파일 키를 입력으로 받지 않는다.

## 파일 수명과 오류 처리

- 임시 테두리는 원본과 같은 비공개 prefix의 서버 생성 키 `<originalKey>.body.png`에 저장한다.
- `JarDesignFinalizeService`는 사진과 테두리를 별도로 영구 복사한다. AI 후보 선택에도 원본 테두리를 유지한다. DB 확정 전 스냅샷은 테두리 키도 비교한다. S3 I/O는 트랜잭션 밖이다.
- 최종 디자인은 실제 CUSTOM일 때만 테두리 키를 기록한다. 다른 외형/이미지 단독으로 돌아간 Draft의 테두리는 정리를 위해 보존한다.
- `AiDraftCleanupService`는 종료 Draft의 테두리와 원본이 모두 삭제돼야 정리 완료를 기록한다. 삭제 실패 시 다음 주기에 재시도한다. 추가 DB 조회 없이 기존 projection에 키를 포함한다.
- DB Draft가 만들어지기 전에 업로드/DB 오류가 발생하면 두 예약 키를 보상 삭제한다. **그 보상 삭제까지 실패하면 DB 행이 없어 현재 스케줄러만으로 자동 재시도를 보장하지 않는다.** 기존 임시 영역 수명 정책/운영 대조가 필요하다. 최종 복사 보상 삭제 실패도 기존 영구 영역 운영 대조 정책을 따른다.

- 운영 S3 비공개 정책/업로드·읽기·복사·삭제 권한과 GET CORS, 실제 모바일 터치/저사양 GPU는 별도 검증이 필요하다. 여기의 로컬 검증은 운영 배포 완료를 뜻하지 않는다.

## 2026-10-13 앞뒤 몸통과 사진 면의 볼륨 확장

- 이전에는 테두리만 부풀리고 사진은 평평한 DOM 레이어로 표시했다. 이제 사진 면도 내부 정점을 분할해 앞뒤 대칭의 볼록한 곡면으로 만든다. 옆 연결선은 0.025로 유지하고 테두리 연결 깊이는 0.46→0.30, 사진 안쪽의 추가 볼륨은 한쪽 최대 0.22다. 사진을 넣은 최대 전체 깊이는 약 0.74이며 빈 틀은 실제 구멍을 유지한다.
- 수정: `body3DGeometry.mjs`, `body3DMesh.mjs`, `components/CustomJarBody3D.jsx`. 추가: `body3DPhoto.mjs`와 테스트. 기존 사진 배치/원본/테두리 PNG/XY 경계/API/DB는 변경하지 않는다. 사진 속 인물이나 사물의 실제 뒷모습·코·팔다리를 생성하는 기능은 아니다.
- 3D 사진은 별도의 재질 그룹과 480×480 Canvas 텍스처로 곡면에 입힌다. 앞뒤 UV가 같으므로 실제 회전으로 좌우 반전된다. 기존 확대·이동·전체 보기와 픽셀 스타일을 유지한다. 입구 장식은 사진 곡면 높이에 맞춰 투영하고 뒷면에는 숨긴다.
- 높이는 고정 129×129 격자/160회 보정으로 계산하고 전체 삼각형 상한 40,000개는 유지한다. 회전·사진 배치 변경은 geometry를 재생성하지 않는다. 같은 URL의 배치만 변경하면 디코딩 이미지/Canvas/텍스처도 재사용한다. 종료 시 모든 geometry/material/texture와 비동기 이미지 콜백을 정리한다.
- CORS/사진 텍스처 실패나 지원하지 않는 미저장 배경 마스크가 있으면 설명과 함께 기존 2D로 복구한다. 편집 마스크를 무시하거나 운영 이미지/저장 데이터를 변경하지 않는다. 새로 3D 사진도 GET CORS를 사용하므로 운영 버킷 확인은 별도로 필요하다.
- Node 회귀 테스트 161개 통과. 확대/전체 보기 텍스처 배치, 앞뒤 곡면·UV·대칭, 빈 구멍, 복잡한 외곽과 카메라 범위 포함. 백엔드는 이번 추가 변경이 없어 재실행하지 않았다.
- 프론트 빌드 성공(기존 500kB 청크 경고 유지). 로컬 합성 사진/다색 고양이에서 실제 볼록한 앞뒤 면, 뒷면 글자 반전/입구 숨김, 사진 확대/전체 보기 변경 시 회전 유지, 390px 모바일 가로 넘침 없음, context 손실 뒤 2D 복구를 확인했다. 실제 운영 S3/CORS와 저사양 기기는 미검증이다.

## 2026-10-13 3D 수평 바닥 마감

- 이전에는 원본 외곽의 아래쪽도 그대로 둥글게 부풀렸다. 이제 `body3DBase.mjs`가 물체의 세워진 방향에서 가장 아래쪽만 수평으로 자르고 실제 바닥 면으로 닫는다. 화면의 아래쪽을 매 회전마다 바꾸는 방식이 아니며 위아래/좌우 연속 회전은 유지한다.
- `body3DMesh.mjs`의 공통 완료 단계에서 사진을 담은 틀과 빈 틀에 함께 적용한다. 전체 높이의 최대 3.5%와 사진 창까지 간격의 절반 중 작은 값만 다듬는다. 3D 아래 끝은 조금 달라질 수 있지만 원본/2D 외곽 좌표, 테두리 PNG, 사진 창/사진 UV/배치, 앞뒤 볼륨, API/DB는 변경하지 않는다.
- 절단된 실제 교차선을 연결해 닫힌 고리별로 삼각형을 만든다. 발이 나뉘면 각각 같은 높이의 바닥을 만들고 그 사이를 사각형이나 볼록 껍질로 메우지 않는다. 바닥 정점의 법선을 분리해 곡면처럼 울퉁불퉁하게 조명되지 않도록 한다. 퇴화한 면은 제외하고 GPU와 같은 Float32 좌표에서 바닥을 검증한다.
- 계산은 틀 geometry 생성 때만 실행하며 회전/사진 배치 변경에서는 재사용한다. 교차점 탐색은 공간 버킷으로 제한하고 삼각형 40,000개 상한과 최대 3회 교차선 보정만 허용한다. 중간 geometry를 정리하고 최종 법선/경계 구는 한 번만 계산한다. 안전한 사진 간격이나 닫힌 교차선을 얻지 못하면 기존 오류 처리로 2D 원본을 유지한다. 별도 라이브러리/네트워크 요청은 없다.
- 수정/추가 파일: `frontend/src/features/jarDesign/body3DBase.mjs`, `body3DMesh.mjs`, `body3DBase.test.mjs`, `body3DMesh.test.mjs`, `frontend/tests/fixtures/body3DShapes.mjs`, `frontend/tests/jar-body-3d-preview.jsx`, 이 문서. 바닥 교차점은 옆벽 삼각형 대각선에 따라 앞뒤의 추가 정점 위치가 다를 수 있으므로 원래 곡면 정점 대칭과 실제 바닥 경계의 기하학적 대칭을 구분해 테스트한다.
- Node 전체 166개 통과, Vite 빌드 성공(기존 500kB 청크 경고 유지), `git diff --check` 오류 없음. 바닥 전용 5개 테스트는 둥근/뾰족한/역방향/깊은 굴곡/가는 팔다리, 아래에서의 Raycast, 두 발 사이 빈 공간, 사진 좌표와 원본 보존, 평면 법선, 앞뒤 대칭, 불가능한 입력 거절을 포함한다.
- 로컬 브라우저의 합성 이미지로 1280px PC와 390px 모바일에서 다색 고양이/뾰족한 끝/두 발의 바닥 표시, 정면 복귀, 가로 넘침 없음, context 손실 시 2D 복구를 확인했다. 사용자 스크린샷의 실제 저장 좌표, 운영 배포, 실제 저사양 기기/터치, 실물 제작의 무게중심/넘어짐은 별도 확인이 필요하다. 물리 시뮬레이션이나 실물 제조용 모델을 보장하지 않는다.
- 이번 수평 바닥 변경에는 백엔드/API/DB 수정이 없어 백엔드 테스트를 다시 실행하지 않았다. 기존 미커밋 변경은 유지했고 커밋/푸시/운영 배포는 실행하지 않았다.
