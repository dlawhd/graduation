## 5. 확실하게 줄어든 작업은 무엇인가?

500명 세 구간의 엔티티 로딩 합계를 완료한 조회 수로 나눴다. 쪽지 요청만이 아니라 목록·상세·쪽지를 합한 동일 비율의 조회 기준이다.

| 버전 | 완료 조회당 엔티티 로딩 |
| --- | ---: |
| 서비스 수정 전 | 14.1994개 |
| JWT만 수정 | 14.1991개 |
| 최종 수정 | 2.2002개 |

**엔티티 로딩 감소율 = (14.1993658 − 2.2002171) ÷ 14.1993658 × 100 = 약 84.50%.**

엔티티 로딩 감소율이며 전체 자바 객체 생성량·heap 사용량·응답 시간 감소율은 아니다. 목록 전용 조회 값과 태그 목록 등은 여전히 생성된다.

실제 MariaDB 회귀 검사에서도 두 쪽지의 목록 조회를 비교해 기존에는 쪽지·작성자 엔티티가 3개 이상 로딩되고 새 조회는 0개인 것을 확인했다. 내용·작성자·태그·ID 순서·페이지 정보는 같았으며 목록과 개수를 위한 SQL은 두 번이었다.

500명 조회 구간의 정상 요청 표본에서 SQL 수는 전후 모두 목록 6·상세 6·쪽지 10회였다. 기존에도 작성자와 부가 정보를 묶어 읽고 있었으므로 N+1을 새로 해결했다고 설명하지 않는다.

이번 아홉 500명 구간에서는 Full GC(메모리 전체를 정리하는 작업)가 0회였다. 최종 버전의 가장 긴 관측 GC 정지는 약 62.36ms였다. GC가 영원히 발생하지 않는다는 뜻은 아니며, 설정까지 함께 바꾸어 효과를 섞지 않았다.
