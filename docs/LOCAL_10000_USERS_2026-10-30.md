# 로컬 1만 계정 저장 상태의 로그인·조회 시험

2026-10-30 실행 완료. **새 임시 DB에 사용자 10,000개를 생성하고 로그인·조회 시험을 통과한 뒤, 앱 테이블 24개의 데이터가 모두 0건으로 돌아왔음을 확인했다. 임시 컨테이너와 네트워크도 각각 0개다.** 운영 서버와 운영 DB는 연결하지 않았다.

이번 시험은 **계정 1만 개가 저장된 상태**를 확인한 것이다. 실제로 로그인하는 계정은 10개이고, 조회 동시 사용자는 1명 → 5명 → 10명이다. 1만 명 동시 접속이나 운영 서버 용량을 검증한 결과로 표현하지 않는다.

## 1. 기존 환경과 어떻게 분리했나?

- 기존 로컬 `graduation-local-db`를 사용하지 않고 GUID 이름을 가진 새 MariaDB·앱·k6 컨테이너를 생성했다.
- 로컬 Docker `desktop-linux`만 허용했다. DB·앱·k6는 실행별 `internal` 네트워크 안에서만 통신하고 호스트 포트를 공개하지 않았다.
- 앱 시작 전에 외부 기본 경로 부재와 외부 IPv4·IPv6·메타데이터 TCP 차단 검사를 통과했다.
- 데이터를 넣기 전에 실제 JDBC 목적지가 `db:3306/isolated_e2e`인지 검사하고, Flyway 이력을 제외한 모든 앱 테이블이 비어 있음을 확인했다.
- 실제 Controller·Service·Repository·인증 쿠키·CSRF·JWT·MariaDB를 사용했다. S3·메일·AI 제공자와 자동 오픈·정리 스케줄러는 시험 대역으로 분리했다. 외부 제공자 호출이 없다는 검사도 통과했다.
- 운영 환경변수·AWS 인증정보·Docker 소켓을 시험 앱에 전달하지 않았다. 기존 로컬 DB 컨테이너는 작업 전후 ID·시작 시각이 같았고 계속 실행 중이었다. 기존 DB의 실제 사용자 데이터를 읽어 복사하지 않았다.

## 2. 생성한 데이터

| 항목 | 생성 후 개수 |
| --- | ---: |
| 사용자 | **10,000** |
| 자체 로그인 자격정보 | **10,000** |
| 저금통 | 9,993 |
| 저금통 멤버 | 10,020 |
| 쪽지 | 10,110 |
| 오픈 기록 | 9,993 |

실제 인증·조회용 10명은 기존 fixture를 재사용했다. 각자 난수 비밀번호를 가진 계정이며 저금통 3개에 모두 참여하고, 저금통마다 쪽지 40개가 있다. k6는 이 3개 저금통·120개 쪽지의 내용과 권한·페이지 정보를 검사한다.

배경 데이터용 9,990명은 각자 저금통·소유 멤버·오픈 기록·쪽지 1개를 가진다. 모든 계정은 고유 시험 접두사와 `example.invalid` 이메일을 사용한다. Entity와 기존 PasswordEncoder로 생성하고 실제 회원가입·메일 인증 API는 호출하지 않았다.

배경 계정에는 시험 준비용 난수 암호 하나의 해시를 공유했다. 실제 로그인하는 10명의 해시는 서로 다른 비밀번호로 생성했다. 따라서 이번 계정 생성 시간을 **1만 건의 회원가입·비밀번호 해싱 성능**으로 발표하지 않는다. 준비용 암호·토큰은 공개 결과에 포함하지 않았다.

## 3. 시험 조건

로그인은 계정 10개를 **순차적으로 한 번씩** 수행하고, 조회 부하의 지연 통계와 분리했다. 이후 같은 인증 세션을 사용해 아래 단계를 실행했다.

| 동시 가상 사용자(VU) | 설정 기간 | 시작 시점 | 사용자별 요청 사이 대기 |
| --- | ---: | ---: | ---: |
| 1명 | 20초 | 0초 | 0.2초 |
| 5명 | 20초 | 25초 | 0.2초 |
| 10명 | 30초 | 50초 | 0.2초 |

단계는 겹치지 않으며 동시에 활동하는 사용자는 최대 10명이다. 목록·상세·쪽지 조회 비율은 약 30%·30%·40%이고 쪽지 첫 두 페이지를 번갈아 읽는다. 로그인·조회 응답은 HTTP 상태뿐 아니라 사용자 ID·저금통 ID·권한·멤버 수·쪽지 ID·정렬·페이지 개수까지 검사한다.

조회 API의 기준은 단계별 **p95 ≤500ms, 읽기 오류율 <1%, 각 API 관측 수 >0**이다. p95는 요청의 95%가 이 시간 안에 끝났다는 지연 지표다. 로그인·준비 요청은 이 조회 기준에 섞지 않았다. 오류·지연 기준 초과, 자원 수집 실패, 메모리 사용 92% 이상이나 실행 시간 상한에서는 시험을 중단하도록 했다.

## 4. 실제 결과

**전체 조회 1,975건, 응답 내용 검사 1,975건 성공·0건 실패, 읽기 오류율 0%였다.** 단계별 9개 API 지연 기준도 모두 통과했다.

| 동시 사용자 | 조회 건수 | 저금통 목록 p95 | 저금통 상세 p95 | 쪽지 목록 p95 |
| --- | ---: | ---: | ---: | ---: |
| 1명 | 90 | 29.00ms | 26.16ms | 37.16ms |
| 5명 | 465 | 16.96ms | 17.68ms | 23.70ms |
| 10명 | 1,420 | **14.20ms** | **12.39ms** | **17.53ms** |

10명 단계는 설정 기간 30초에 조회 1,420건으로, **설정 기간 기준 약 47.33건/초**다. 요청 사이 0.2초 대기를 둔 결과이므로 서버 최대 처리량으로 해석하지 않는다. 단계 순서가 1→5→10으로 고정됐고 JVM·DB의 준비 상태가 달라질 수 있으므로, 뒤 단계가 더 빠른 현상을 동시 사용자 증가의 효과나 코드 개선율이라고 설명하지 않는다.

| 순차 로그인 10건 | 관측값 |
| --- | ---: |
| 평균 | 150.61ms |
| 중앙값 | 95.10ms |
| p95 | 405.13ms |
| 최소 ~ 최대 | 76.99 ~ 525.11ms |

비로그인 요청의 **401**, 다른 사용자의 저금통 요청의 **403**도 확인했다. k6 전체 HTTP 실패 지표에 포함된 403 한 건은 이 의도된 권한 거절 검사다. 읽기 부하의 오류율은 별도 `read_errors`로 집계했으며 0%다. 전체 k6 HTTP 2,016건은 조회 1,975건·인증 준비 40건·예상된 비회원 거절 1건으로 구성됐다. Java에서 확인한 비로그인 401은 k6 집계 밖이다.

## 5. 자원 사용 관찰

| 대상 | 제한 | 부하 중 샘플에서 관측한 최대 메모리 | 샘플 최대 CPU |
| --- | --- | ---: | ---: |
| 시험 앱 | 2 CPU, 컨테이너 1,536MiB, JVM heap 768MiB | 671.1MiB | 131.74% |
| 임시 MariaDB | 메모리 768MiB | 417.9MiB | 16.79% |
| k6 | 1 CPU, 메모리 256MiB | 83.32MiB | 100.29% |

각 컨테이너를 17회 샘플링한 값이다. Docker CPU 100%는 대략 CPU 코어 하나에 해당하며 측정 창에 따라 제한 부근의 작은 초과 표기가 가능하다. 이 값은 JVM heap 사용량이나 실제 순간 최대 메모리와 다르다. 데이터 생성 전 구간까지 포함한 전체 실행의 자원 최대값도 아니다.

## 7. 재실행 방법과 검증

프로젝트 루트에서 실행한다. 로컬 Docker Desktop이 필요하며 운영 주소를 입력하는 옵션은 없다.

```powershell
./tools/isolated/run-e2e.ps1 -Dataset10k
```

이 명령은 빌드 → 새 DB·앱 생성 → 계정 생성 → 실제 로그인·조회 → 데이터 삭제 검증 → 임시 자원 제거까지 수행한다. 실패한 부하 시험을 성공으로 바꾸지 않고 종료 코드와 정리 결과를 남긴다. 결과 폴더는 Git 제외 경로인 `build/isolated-e2e-results/`다.

## 9. 결과를 설명할 때

> 운영과 분리한 로컬 MariaDB에 사용자 1만 개와 연관 데이터를 생성하고, 10개 계정의 실제 로그인과 최대 10명 동시 조회를 검증했습니다. 조회 1,975건에서 응답 내용 검사 오류는 0건이었고, 10명 단계의 목록·상세·쪽지 API p95는 각각 14.20ms·12.39ms·17.53ms였습니다. 비로그인·비회원 접근 거절과 테스트 후 전체 앱 데이터 0건 및 임시 자원 제거도 확인했습니다. 이 결과는 로컬의 합성 데이터 시험이며 운영 서버의 1만 명 동시 접속 성능을 의미하지 않습니다.

단일 로컬 실행이며 배경 사용자 전체가 요청한 것은 아니다. 실제 AWS·이미지 처리·3D 화면 출력·메일·AI·장시간 안정성·운영 네트워크 지연은 이번 범위에 포함하지 않는다.
