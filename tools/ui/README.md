# 보관함·초안 로컬 UI 검증

> 2026-11-21: 선택한 도움말·문의 화면을 제품 코드에 적용했다. 아래의 화면 비교 도구는 이전 예시를 보존한다. 현재 적용 상태와 검증은 [사용자 문의 적용 문서](../../docs/SUPPORT_CENTER_2026-11-21.md)를 우선한다.

운영 API·DB·S3를 사용하지 않는 가짜 API 서버다. 저장소 루트의 PowerShell에서:

```powershell
$env:VITE_API_BASE_URL='http://127.0.0.1:18962'
$env:VITE_WS_BASE_URL='ws://127.0.0.1:18962/ws'
npm.cmd --prefix frontend run build -- --outDir ../build/selected-features/frontend
Remove-Item Env:VITE_API_BASE_URL
Remove-Item Env:VITE_WS_BASE_URL
python tools/ui/selected-features-fixture.py
```

- `http://127.0.0.1:18962/jars`: 12개 시험 저금통에서 현재 페이지 밖 검색, 열린/잠긴/즐겨찾기 필터와 별 버튼을 확인한다.
- `/jars/new`: 본인 초안 목록 → 이어서 만들기 → 이름·인원·날짜 입력 후 새로고침 복구를 확인한다.
- `/jars/900001`: 버튼 배치·캘린더 파일·쪽지 초안을 확인한다. 글·사진·첨부 설명을 입력하고 새로고침 후 이어서 쓰기로 복구한다.
- 쪽지 내용에 `응답유실`을 포함해 제출하면 최초 1회는 저장 뒤 503을 반환한다. 새로고침·초안 복구 후 재제출하고 `/fixture-status`의 `notes`가 1인지 확인한다. 가짜 서버의 메모리 데이터는 종료하면 사라진다.
- `/draft-store-test`: 검증 시작 버튼으로 실제 IndexedDB의 글·원본 복구, 계정/저금통 격리, 동시 쓰기 충돌, 완료 정리와 삭제 후 오래된 쓰기 차단을 확인한다. 시험 전용 scope만 사용한다.

이 도구의 메모리 API 결과는 실제 서버의 인증·트랜잭션 검증을 대신하지 않는다. 관련 Java 테스트는 `test` 프로필과 임시 MariaDB를 사용한다. 화면 스크립트·시험 서버는 운영 빌드에 포함하지 않는다.

## 운영 문의함 화면 비교

`node tools/ui/render-operator-inbox-previews.mjs`는 실제 로고·폰트·문의 레이아웃·상태 배지를 재사용한 React 예시 세 가지를 빌드하고 `build/operator-inbox-previews`에 PC·모바일 PNG를 만든다. Chrome 실행 경로는 `MEMORYJAR_TEST_CHROME`으로 지정할 수 있다.

- 카드형, 표형, 목록·대화 분할형을 비교한다. 이 도구 실행으로 제품 화면이 변경되지는 않는다. 현재 제품 코드에는 선택한 분할형을 적용했다.
- 예시 데이터만 사용하고 운영 API·계정·실제 문의에 연결하지 않는다. 버튼과 필터는 예시 화면의 메모리에서만 동작한다.
- 임시 Chrome 프로필과 로컬 HTTP 서버를 사용하며, 렌더링 완료·가로 넘침 여부를 검사한다.

## 실제 운영 문의함 통합 검증

`node tools/ui/operator-inbox.browser.mjs`는 제품의 `SupportInquiriesPage`·`OperatorSupportInbox`·`SupportInquiryDetail`·API 모듈·실시간 재조회 훅을 실행한다. HTTP 서버와 STOMP 전송만 로컬 대역으로 바꾸고, 사용자 Chrome 프로필과 운영 서버에는 연결하지 않는다. 새 패키지를 설치하지 않는다.

21개 시나리오로 상태 필터·커서·오류·답변/첨부 복원·응답 유실 후 재시도·CSRF·첨부 전송·추가 정보 요청·해결/재개·실시간·계정/권한 변경·일반 문의 회귀를 확인한다. 결과 JSON과 1440px PC·390px 모바일 캡처는 `build/operator-inbox`에 저장한다. 공통 헤더는 시험용이고 문의함 본문은 실제 코드다. 서버 권한·트랜잭션 검증은 관련 Java 테스트와 별도로 확인한다.

## 도움말·사용자 문의 화면 비교 (2026-11-20)

1. **파일:** `support-center-preview.jsx`는 추천 화면 여섯 가지와 공통 메뉴를, `support-center-preview.css`는 비교용 스타일을, `render-support-center-previews.mjs`는 빌드·격리 브라우저 검증·캡처를 담당한다. 제품 폰트·로고·상태 배지와 실제 `SupportComposer`·`SupportInquiryDetail`을 재사용한다.
2. **현재 화면:** 도움말의 큰 FAQ 카드 반복, 작성 화면의 넓은 입력/여백, 비어 있는 내 문의의 불필요한 페이지 버튼, 로그인 문의의 작성/내역이 길게 이어지는 배치를 확인했다.
3. **추천 변경:** 공통 하위 메뉴와 제목 간격을 맞춘다. FAQ는 검색·주제 선택·행 목록으로, 내 문의는 상태 중심의 목록으로 표시한다. 작성은 입력과 보조 안내를 PC에서 나란히 두고 모바일은 한 열로 표시한다. 로그인 문의는 작성과 이 브라우저 내역을 탭으로 나눈다. 상세는 기존 대화/추가 설명 기능을 재사용한다.
4. **이유:** 현재 Memory Jar의 크림색·초록색·흰 카드를 유지하며 반복되는 큰 박스와 이동 버튼을 줄이고, 사용자가 해야 할 행동을 쉽게 찾게 한다.
5. **성능·보안·호환성:** 새로운 라이브러리는 없다. FAQ는 현재 서버 Java 코드의 8개 항목을 읽는다. 주제 선택은 이 항목의 로컬 필터다. 일반 문의 목록 API는 커서만 받으므로 서버에 없는 전체 상태 필터·전역 통계는 예시에 넣지 않는다. 비로그인 문의의 브라우저 쿠키 범위·첨부 형식/용량·보관 기간·중복 전송 방지는 기존 정책을 따른다. 비교 화면은 가짜 문의만 사용하며 API와 실시간 전송은 대체한다. 예시 페이지의 외부 연결도 제한한다.
6. **실행:** 저장소 루트에서 `node tools/ui/render-support-center-previews.mjs`를 실행한다. 설치된 프론트 라이브러리와 Chrome을 사용한다. 다른 Chrome 경로는 `MEMORYJAR_TEST_CHROME`으로 지정한다.
7. **검증:** 여섯 화면을 1440px·390px에서 빌드·렌더링하고, 가로 넘침 없음과 모바일 입력란 폭을 확인했다. 검색/주제 선택/빈 검색, 문의 이동, 실제 폼 유효성 검사·대체 접수, 로그인 문의 작성/내역 탭과 상세 이동을 검사했다. 기본 12장과 로그인 내역 2장을 만든다. 캡처를 직접 확인했다. 실제 API 호출은 0건이다. 제품 전체 테스트나 실제 서버 검증을 수행한 결과는 아니다.
8. **범위:** 실제 제품의 도움말·문의 파일은 이 요청으로 변경하지 않았다. 선택을 위한 예시다. 적용할 때는 현재 로그인/비로그인 라우트, 권한 검사, 문의/첨부 API를 유지하면서 화면에 연결하고 별도의 회귀 검증을 해야 한다. 운영 배포·DB 변경·실제 문의 접수는 하지 않는다.

## 실제 사용자 도움말·문의 검증 (2026-11-21)

저장소 루트에서 `node tools/ui/support-center.browser.mjs`를 실행한다. 제품의 4개 페이지, 작성/상세 컴포넌트, API/CSRF 모듈, 실시간 재조회 훅을 사용한다. HTTP와 소켓 전송만 로컬 대역이다. `isolated-support-browser.mjs`는 새 임시 Chrome 프로필만 제어한다.

22개 시나리오로 검색·문맥 전달·접수/첨부 응답 유실·중복 차단·답변/해결·커서·실시간·계정 전환·게스트 쿠키/탭/권한을 확인한다. 비로그인 문의의 웹소켓 미구독도 확인한다. 결과와 실제 제품 본문 캡처는 `build/support-center`에 저장한다. 캡처의 공통 헤더·데이터는 시험용이며 운영 서비스 검증 결과는 아니다. 일반 문의함과 공통 컴포넌트를 바꿨을 때는 기존 `operator-inbox.browser.mjs`의 운영자 회귀 검증도 함께 사용한다.
