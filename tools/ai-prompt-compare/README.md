# Draft #44 — 귀여운 2D / 손그림 비교 도구

이 폴더에는 인증정보나 사용자 사진이 없습니다. 기괴/픽셀/3D/수채화는 호출하지 않습니다.
DB는 읽기 전용 트랜잭션의 SELECT만, S3는 원본 GET만 수행합니다.
API 컨테이너를 재시작하거나 Spring, Flyway, 스케줄러를 추가 실행하지 않습니다.
현재 Draft가 ACTIVE이고 미만료이며 기존 #131/#134가 연결되어 있고 생성 중 요청이 없어야 합니다.

## 1. 서버로 전달

로컬에서 `./gradlew aiPromptComparisonBundle --offline`로 만든
`build/distributions/memoryjar-ai-prompt-compare.zip`을 내려받아 SSH/SFTP로 서버에 전달합니다.
파일에 비밀값은 없지만 무결성을 확인하기 위해 로컬 SHA-256과 서버 `sha256sum`을 비교합니다.
웹 공개 폴더가 아닌 새 관리자 전용 폴더에 압축을 풉니다.

예시 (서버에서, ZIP은 아래 경로로 업로드한 상태):

```bash
umask 077
mkdir -m 700 /home/ubuntu/deploy/ai-prompt-compare-v1
python3 -m zipfile -e /home/ubuntu/memoryjar-ai-prompt-compare.zip /home/ubuntu/deploy/ai-prompt-compare-v1
cd /home/ubuntu/deploy/ai-prompt-compare-v1
bash run.sh prepare
```

이미 폴더가 있으면 덮어쓰지 말고 작업 이력을 확인합니다. 새 폴더를 써도 이전 결과는 삭제하지 않습니다.
위 압축 해제는 서버에 설치된 Python 3의 표준 라이브러리만 사용합니다. 별도 `unzip` 설치는 필요 없습니다.
PC 터미널에서 실행하려면 SSH로 서버에 접속한 뒤 수행합니다. `/home/ubuntu/`는 PC 경로가 아닙니다.

## 2. 먼저 사전 점검 (AI 0회)

`PREFLIGHT_OK ... aiCalls=0`가 나와야 합니다.
`COMPARE_ABORTED phase=...`이면 멈추고 그 한 줄만 공유합니다. 인증정보나 전체 예외를 출력하지 마세요.
환경변수 누락/다른 모델/출력 크기/배포된 기존 프롬프트가 다르면 호출 전에 멈춥니다.
DB URL/계정과 Cloudflare, AWS 인증은 기존 컨테이너 안에서만 읽습니다.
별도 JVM은 최대 256MiB로 제한하지만 API 컨테이너의 CPU/메모리를 공유합니다.
트래픽이 낮은 시간에 실행하고 여유 메모리를 먼저 확인하는 것을 권장합니다.

## 3. 비교 실행 (최대 4회, 생성 사용량 발생)

사전 점검 통과 뒤 **한 번만** 실행합니다.

```bash
bash run.sh run
```

- CUTE_2D_OLD / CUTE_2D_NEW / HAND_DRAWN_OLD / HAND_DRAWN_NEW 순서입니다.
- 동일한 저장 장면 PNG, 모델, 1024×1024, 명시적 seed 20261006을 사용합니다.
- 자동 재시도는 없습니다. 인증 오류/명확한 정책 거절/입력 오류/할당량/용량 부족은 남은 요청도 중단합니다.
- 출력 차단 분류 보강을 배포한 서버에서는 확인된 `OUTPUT_IMAGE_FLAGGED`도 정책 거절로 분류해 나머지 호출을 중단합니다.
- 실행 표시 파일을 생성하므로 중복 실행이나 실패 후 반복 실행은 막힙니다. 그 파일을 지워서 재실행하지 마세요.
- 사전 점검 이후 컨테이너/JAR/사진 배치가 바뀌거나 Draft가 종료되면 중단합니다.
- DB에 Generation을 추가하지 않고 S3에도 저장하지 않습니다. 웹 화면 후보는 바뀌지 않습니다.
- Rekognition은 호출하지 않습니다. PROVIDER_OK_IMAGE_VALID는 제공자/이미지 규격 성공이지 서비스 전체 성공이 아닙니다.
- 비교 도중 해당 Draft를 편집/생성/최종화하지 마세요. 이 도구는 서비스 잠금을 잡지 않고 로컬 불변 입력을 사용합니다.
- 과거 #131/#134의 seed는 미지정이었습니다. 이 실행은 당시 시도를 그대로 재현하거나 성공률을 통계적으로 증명하지 않습니다.

## 4. 공유할 결과와 비공개 자료 구분

터미널에는 고정 trial ID, 분류 enum, HTTP 상태, 숫자 코드, 검증된 CF-Ray, 처리 시간만 출력합니다.
`private-results/copy.*/summary.safe.tsv`와 `*.result.safe.txt`, `*.diagnostic.safe.txt`만 공유할 수 있습니다.
도중 중단이면 완료한 `*.result.safe.txt`만 확인합니다. 요약에는 토큰, 오류 원문, 프롬프트, 사진이 없습니다.

**`*.error.private`에는 제공자 오류 원문이 있으므로 채팅/Git/공개 게시물에 첨부하지 않습니다.**
관리자가 서버에서 비공개로 확인하고, 인증정보/입력 인용이 없는 원인 문장인지 먼저 판단합니다.
이 파일은 최대 65,537바이트이며 더 큰 오류는 잘린 진단 자료입니다. 원문은 정확한 분류를 검증할 때만 사용합니다.
이미지/원문은 0700 폴더 안의 0600 파일로 생성합니다. 서버 결과 폴더를 통째로 압축해 공유하지 마세요.
관리자/root는 파일을 읽을 수 있습니다. 절대적인 비밀 저장소나 암호화 저장이라는 뜻은 아닙니다.

생성된 `*.png`와 `input.png`는 먼저 관리자가 확인한 뒤 품질 비교에만 전달합니다.
대상 수/배치/얼굴/색상/귀여운 2D 또는 색연필 표현을 비교한 뒤 운영 적용 여부를 결정합니다.
프롬프트 적용, 배포, 운영 후보/콘텐츠 심사 검증은 다음 단계이며 이 도구가 자동으로 하지 않습니다.
임시 결과는 컨테이너 교체 시 사라질 수 있으므로 호스트의 private-results 회수 경로를 보존하세요.

## 로컬 검증과 실행 경계

일반 `test`, `bootJar`는 외부 AI를 호출하지 않습니다. 전용 비교 JAR도 일반 bootJar에 포함되지 않습니다.
mock 응답으로 원문 분리/본문 상한/기존 오류 분류 유지/두 스타일만 비교/중단 조건을 검사합니다.
실제 운영 DB 연결, S3 읽기와 유료 생성의 성공 여부는 서버 실행 결과로 별도 확인해야 합니다.
